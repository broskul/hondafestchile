# Cloudflare R2

## Alcance

Cloudflare R2 aloja los frames versionados del hero animado. El poster inicial permanece dentro del sitio para asegurar una primera pintura inmediata y un fallback independiente del CDN.

## Configuracion verificada

- Bucket: `hondafestchile`.
- URL publica de desarrollo: `https://pub-a4778145aed5476ca3ad2d9e9ca35aa3.r2.dev/hfc-web/HeroWeb`.
- Manifiesto consumido por la web: `public/hero-animation-manifest.json`.
- Fuente local: `C:\Users\Usuario\Downloads\HFC\HeroWeb`.
- Publicacion reproducible: `npm run hero:r2:upload`.

La URL `r2.dev` tiene limite de uso y Cloudflare no la recomienda como entrega productiva. Antes del lanzamiento publico debe configurarse un dominio personalizado para el bucket y actualizarse `cdnBaseUrl` en el manifiesto.

## Release del hero

- Version: `hfc-hero-racing-v1`.
- Runtime esperado: 87 objetos y 9.072.153 bytes bajo el prefijo `hfc-web/HeroWeb/`.
- Variantes: AVIF 2560, WebP 1920 y AVIF 1280, todas con 28 frames reproducidos a 6 fps.
- Posters remotos: AVIF 2560 y WebP 1920.
- Cache de objetos: `public, max-age=31536000, immutable`.
- La estructura remota replica el paquete: `frames/<variante>/`, `posters/` y `manifest.json`.

El script `scripts/upload-hero-r2.js` firma las solicitudes S3, publica con concurrencia acotada y vuelve a descargar cada objeto para comparar bytes y SHA-256. Solo puede declararse la carga completa cuando informa 87 objetos verificados.

## Estado actual

El bucket y su acceso publico fueron verificados el 26 de agosto de 2026. El usuario publico manualmente el paquete `HeroWeb` bajo `hfc-web/HeroWeb/` el 27 de agosto de 2026. La carga desde el panel no asigno `Cache-Control: immutable` a los objetos observados. El script de publicacion conserva ese encabezado para futuras reposiciones; una optimizacion de cache y un dominio personalizado siguen pendientes antes de produccion.
